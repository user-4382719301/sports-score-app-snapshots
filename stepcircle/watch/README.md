# Smartwatch support

## The important part: watches work with zero watch-side code

StepCircle reads activity from the platform health store, and every major
watch already syncs into it:

| Watch | Syncs into | Read by |
|---|---|---|
| Apple Watch | HealthKit | `src/health/healthKitAdapter.ts` |
| Wear OS (Pixel Watch, etc.) | Health Connect | `src/health/healthConnectAdapter.ts` |
| Samsung Galaxy Watch | Health Connect (via Samsung Health) | same |
| Fitbit | Health Connect (via Fitbit app) | same |
| Garmin / others | Health Connect (via vendor app) | same |

Both stores de-duplicate overlapping phone + watch samples, so a user
wearing a watch automatically gets watch-quality step counts in the phone
app — rings, streaks, sharing and competitions all included.

## Optional native companions (this directory)

For users who want rings on their wrist, this directory contains reference
implementations of small native companion apps:

- `watchos/` — SwiftUI watchOS app: rings on the watch face, live step
  count, queried directly from HealthKit on the watch.
- `wearos/` — Compose for Wear OS app: rings + steps, read from Health
  Services / Health Connect.

These are starting points, not part of the Expo build:

- **watchOS** targets must be added to the iOS project generated by
  `npx expo prebuild` (open `ios/StepCircle.xcworkspace`, File → New →
  Target → watchOS App, then drop in the Swift files). Enable the HealthKit
  capability on the watch target.
- **Wear OS** is a separate Gradle module/app (`com.stepcircle.wear`)
  signed with the same key and package prefix so the Play Store offers it
  alongside the phone app.

Neither companion needs custom phone↔watch messaging for step data — the
health stores are the sync channel. If you later want richer sync (e.g.
pushing competition standings to the watch), use `WCSession` on iOS and the
Wearable Data Layer on Android.
